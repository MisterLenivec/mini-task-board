# Mini Task Board

Небольшая локальная доска задач и учебный проект агентной разработки в Codex.

## Возможности

- Создание, просмотр, редактирование и удаление задач.
- Название, описание и статусы `todo`, `in_progress`, `done`.
- Три колонки, фильтр и смена статуса списком или перетаскиванием.
- Сохранение задач в SQLite между запусками.
- Русский адаптивный интерфейс, клавиатурное управление, обработка ошибок API.

Стек: Python 3.12, FastAPI, SQLAlchemy 2, SQLite, Pydantic v2, HTML/CSS/vanilla JavaScript. Проверки: pytest, httpx, Ruff, pytest-playwright и Chromium. Отдельная frontend-сборка не нужна.

Разработка интегрирована в `dev`. `main` сохраняет начальную инициализацию до отдельного разрешения выпуска.

## Запуск в WSL2

```bash
cd /home/leniva/projects/mini-task-board
```

Если окружение ещё не подготовлено:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Запустите сервер:

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте в браузере Windows http://localhost:8000. Документация API: http://localhost:8000/docs. Для остановки сервера нажмите Ctrl+C в терминале. Приложение рассчитано на локальное использование одним пользователем.

## Данные

SQLite-файл — `data/task_board.sqlite3` относительно корня проекта, независимо от cwd. Он создаётся при первом запуске и не попадает в Git. Переменная `TASK_BOARD_DB_PATH` задаёт альтернативный путь. Перезапуск сохраняет задачи; не удаляйте файл БД ради обновления приложения. Перед изменением используемой схемы требуется отдельная миграция.

## Проверки

Один раз скачайте Chromium внутри .venv:

```bash
PLAYWRIGHT_BROWSERS_PATH=0 .venv/bin/python -m playwright install chromium
```

Запустите проверки из корня проекта:

```bash
.venv/bin/python -m ruff check .
.venv/bin/python -m ruff format --check .
PLAYWRIGHT_BROWSERS_PATH=0 .venv/bin/python -m pytest
```

API-тесты, реальные HTTP-запросы, перезапуск сервера и Chromium используют временные БД; пользовательский SQLite-файл не открывается. CI устанавливает браузер и Linux-зависимости автоматически. Проверкам нужны loopback-сокеты: внутри ограниченного sandbox Codex может потребоваться разрешённый запуск вне изоляции. Пропущенные или недоступные обязательные проверки не считаются успешными.

## Ручная приёмка

1. Создайте несколько задач с описаниями и разными статусами.
2. Отредактируйте задачу, затем проверьте отмену редактирования.
3. Измените статус списком и перетащите карточку за заголовок в другую колонку.
4. Примените фильтр, проверьте три видимые колонки и сбросьте фильтр.
5. Обновите страницу и перезапустите сервер — задачи должны сохраниться.
6. Удалите задачу: сначала отмените подтверждение, затем подтвердите.

Перетаскивание меняет только статус; порядок внутри колонок определяется id. На клавиатуре и сенсорном экране используйте список статуса.
