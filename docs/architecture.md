# Архитектура

## Границы MVP

Одно локальное приложение для одного пользователя. Один процесс Uvicorn/FastAPI отдаёт HTML, CSS, JavaScript и JSON API с одного origin. Интерфейс на русском. Публикация сервера, регистрация, аккаунты, Docker, Redis, Kafka, React и фоновые процессы не входят в MVP.

Поток данных: браузер → fetch → FastAPI → синхронный SQLAlchemy 2 → SQLite. Синхронные обработчики и сессия на запрос достаточны для локальной доски. Отдельные слои service/repository не нужны.

## Ответственность модулей

Целевая структура (модули реализации создаются позднее):

```text
app/
  __init__.py
  main.py          # create_app(db_path=...), lifespan, страница и статика
  db.py            # engine, сессия на запрос, инициализация таблицы
  models.py        # ORM-модель и допустимые статусы
  schemas.py       # Pydantic v2: создание, обновление, ответ
  routes.py        # CRUD и фильтрация через SQLAlchemy
  static/
    index.html
    styles.css
    app.js
tests/
  conftest.py
  api/
  e2e/
```

## Хранение

Одна таблица `tasks`; точные поля и ограничения описаны в [контракте](api-contract.md).

БД по умолчанию: `data/task_board.sqlite3` относительно корня проекта, независимо от cwd. Переопределение: `TASK_BOARD_DB_PATH`. Фабрика `create_app(db_path=...)` принимает отдельный путь для тестов. Пользовательские данные, `.venv` и артефакты проверок не попадают в Git.

Инициализация через SQLAlchemy `create_all()` в FastAPI lifespan. Существующие данные сохраняются; при остановке ресурсы освобождаются. `create_all()` не обновляет существующую схему. Перед первым изменением используемой схемы отдельно проектируется миграция; удаление БД ради обновления запрещено. Alembic пока не добавляется.

## Интерфейс

Три колонки: «К выполнению», «В работе», «Готово». Общая форма создания/редактирования, подтверждение удаления. Статус меняется списком или нативным drag-and-drop между колонками; оба способа вызывают один PATCH. Сортировка внутри колонки по id; ручная перестановка не сохраняется. Список статусов доступен с клавиатуры и на сенсорных устройствах.

Фильтр «Все статусы / К выполнению / В работе / Готово» вызывает GET с необязательным status. Все три колонки видимы. Карточка, сменившая статус за пределы фильтра, исчезает из результата.

После успешной записи список загружается заново. До ответа сервера прежнее состояние сохраняется. Повторные действия на время запроса блокируются. Предусмотрены загрузка, пустая доска и ошибка. Пользовательский текст выводится через textContent, без HTML-интерпретации.

## Зависимости и проверки

Python 3.12; FastAPI, Uvicorn, SQLAlchemy 2, Pydantic v2. Инструменты: pytest, httpx, Ruff, pytest-playwright и Chromium. Позднее зависимости устанавливаются в `.venv`, проверенные версии с транзитивными зависимостями фиксируются в requirements.txt. pyproject.toml содержит настройки инструментов; отдельная production-сборка не нужна.

Контрактные тесты используют изолированное приложение и временный SQLite-файл. Интеграционные проверки делают настоящие HTTP-запросы к запущенному Uvicorn; Playwright проверяет реальный интерфейс. Тесты не открывают пользовательскую БД.
